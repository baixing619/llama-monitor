# LlamaMonitor — 本地推理服务状态监控窗口

[English documentation](README.en.md)

一个独立的 Windows 桌面小窗口，用来看本机跑着的**本地大模型推理服务**现在在干什么：
谁在跑、模型是什么、GPU 吃多少、生成多快、上下文占了多少、日志在刷什么。

**只读取服务状态。** 不写服务端配置、不发推理请求、不改你的模型文件；程序会写本地诊断日志。

**v0.2.0** 新增服务运行时间、Mini 浮窗和保留阅读位置的日志刷新，并修正槽位 token 用量的计算。

快速开始：从 [GitHub Releases](https://github.com/baixing619/llama-monitor/releases) 下载 Windows 压缩包，解压后双击 `启动监控.cmd` 或 `LlamaMonitor.exe`。源码仓库不含 EXE，编译方式见下文。

## 一、运行环境要求

### 系统

| 项目 | 要求 |
|---|---|
| 操作系统 | **Windows 10 版本 1809（build 17763）或更高**，推荐 **Windows 11** |
| 系统类型 | 64 位（x64） |
| 架构 | x64 原生；ARM64 走 x64 模拟 |

> 为什么要求 1809 以上：程序读取其它进程命令行用到了
> `NtQueryInformationProcess(ProcessCommandLineInformation)`，这个接口从 Windows 8.1 起提供，
> Windows 10 1809 起在所有 SKU 上稳定可用。低于此版本会自动退回"按端口探测"，功能受限。
>
> Windows 7 / 8 / 8.1 **未经测试**，不保证可用。

### 运行库

在标准 Windows 10/11 安装中，运行本工具无需另装 .NET SDK 或 Visual C++ 运行库；程序使用系统的 .NET Framework 4.x。

| 依赖 | 是否需要单独装 | 说明 |
|---|---|---|
| .NET Framework 4.x | ❌ **系统自带** | Win10 1809+ / Win11 全部预装 4.6.2 以上 |
| Visual C++ 运行库 | ❌ 不需要 | 不依赖 MSVCRT |
| Node.js / Python / PowerShell | ❌ 不需要 | 单文件原生程序 |
| CUDA 工具包 | ❌ 不需要 | 只用 `nvidia-smi` 查显卡，没有也能用 |
| 显卡驱动 | 可选 | 有 NVIDIA 驱动才能显示显卡那行 |

如果**确实**遇到 .NET Framework 缺失提示（一般只在精简版系统或 Windows 7 上），
从微软官方安装：

- **.NET Framework 4.8 离线安装包（x64，约 68 MB）**
  <https://go.microsoft.com/fwlink/?linkid=2088631>
- 网页版入口（选 **Runtime**，不要选 Developer Pack）
  <https://dotnet.microsoft.com/download/dotnet-framework/net48>

> 检查本机是否已装：`Win+R` → `regedit`，看
> `HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\NET Framework Setup\NDP\v4\Full` 的 `Release` 值。

  不影响推理服务本身的监控。

## 二、支持哪些推理服务

**自动发现，不需要填端口或路径。** 识别方式：先找相关进程，从进程命令行读出真实端口和日志路径；
读不到就按常见端口逐个探活。

| 服务 | 默认端口 | 能拿到什么 |
|---|---|---|
| **llama.cpp**（`llama-server`） | 8080 | 槽位 token 用量/上限、预填充/缓存/输出计数、每槽速度、KV 池、任务级吞吐、日志 |
| **Ollama** | 11434 | 模型列表、运行状态 |
| **LM Studio** | 1234 | 模型列表、运行状态 |
| **vLLM** | 8000 | 模型列表、累计生成 token（可算整体吞吐） |
| **SGLang** | 30000 | 模型列表、运行状态 |
| **KoboldCpp** | 5001 | 模型列表、运行状态 |
| **text-generation-webui** | 5000 | 模型列表、运行状态 |
| **LocalAI** | 8080 | 模型列表、运行状态 |
| **TabbyAPI** | 5000 | 模型列表、运行状态 |

除 llama.cpp 外，其它后端**不提供槽位级数据**，所以那两块表格会自动隐藏，只显示模型和存活状态。
这是后端 API 的限制，不是程序的问题。

自定义端口：`LlamaMonitor.exe --port 9999`

看看当前能发现什么（不开窗，纯命令行；使用控制台版程序）：

```
LlamaMonitor-cli.exe --list
```

## 三、界面说明

```
┌──────────────────────────────────────────────────────────────┐
│ ● 服务在线  http://127.0.0.1:1235  [llama.cpp · 进程 PID ...] │ ← 状态 + 怎么发现它的
│ 模型 xxx | 槽位 2 个 | 版本 b10819 | 日志 xxx.log             │ ← 模型与日志来源
│ 显卡0 54% | 241瓦 | 76℃ | 显存 21603/24576 兆  ‖ 显卡1 …     │ ← 每张卡实时状态
│ 连续运行 01:23:45                                             │ ← 服务运行时间
├──────────────────────────────────────────────────────────────┤
│ 槽位实时                                                      │
│  槽 任务 状态 已预填充 缓存 输出 当前速度 … 槽 token 用量/上限 │
├──────────────────────────────────────────────────────────────┤
│ 各任务时刻（来自服务日志）                                     │
│  槽 已生成数 生成速度 近三秒速度 草稿接受率 … 最后更新          │
├──────────────────────────────────────────────────────────────┤
│ 键值缓存池 22,221 / 400,384 (5.5%)  安全余量 1024 …            │
│ 服务日志尾巴                                                  │
│  [日志原文实时滚动]                                            │
├──────────────────────────────────────────────────────────────┤
│ [03:15:14]  刷新 13 次   间隔 1000 ms   警告 108 次            │ ← 状态栏
└──────────────────────────────────────────────────────────────┘
```

### 各栏含义

**服务运行时间**：能读取本机监听进程时，`连续运行`从该进程的实际启动时间计算。无法取得进程启动时间或连接远程服务时，显示明确标注的`观察在线`时长，表示本次连续观察到服务在线的时间，不代表服务已运行的总时长。离线后旧时长不可用，重新连接或切换服务后重新确认来源。

**槽位实时**（来自服务端 `/slots`）

- `状态`：处理中 / 空闲
- `已预填充 token` / `缓存 token`：接口提供的预填充和缓存计数；缺少字段时显示 `—`，不推算提示词处理百分比或缓存命中率
- `输出 token`：接口提供的已生成计数；兼容顶层和 `next_token.n_decoded`，缺少时显示 `—`
- `当前速度` / `近三秒`：两个时间窗的生成速度；空闲或生成计数未知时显示 `—`
- `槽 token 用量 / 上限`：当前槽直接保留的 token 数 / `n_ctx`，已知上限时附带占用比例。优先用 `n_past`；没有该字段时用 `n_prompt_tokens`。当前 llama.cpp 的 `n_prompt_tokens` 已包含生成 token，**不能再加一次已生成计数**

空闲槽仍可能保留上下文，因此空闲不等于 token 用量为零。未知计数或上限显示 `—`；服务离线时清除旧槽位数据，避免把上一次的状态当成当前值。

**各任务时刻**（从服务日志解析）

- `已生成数`：该任务累计生成量
- `生成速度` / `近三秒速度`：服务端自报的 `tg` 与 `tg_3s`
- `草稿接受率`：投机解码（MTP）的草稿命中比例，括号内为 命中/生成
- `预填充进度`：服务日志上报的预填充进度
- `最后更新`：最后一次上报时间 + 当时处于"预填充"还是"生成"阶段

**键值缓存池**：当前占用 / 总量、安全余量、默认输出预留、排队策略。
只有带 `kv_budget_guard` 的定制构建才有这一行，官方 llama.cpp 没有，此时该行自动隐藏。

**服务日志尾巴**：显示日志原文。停在底部时跟随新行；向上滚动阅读后，刷新会保留阅读位置和文字选择。点击`到底部`恢复查看最新日志。警告与错误次数放在底部状态栏。

**状态栏**：最后刷新时间、刷新次数、刷新间隔、警告次数。

### 按钮与快捷键

- `置顶`：窗口是否始终在最前
- `暂停`：暂停刷新（数据保持不变）
- `看日志`：用记事本打开正在读的日志
- `WebUI`：打开服务自带的网页界面（端口 = 服务端口 + 1）
- `EN / 中文`：切换界面语言。默认跟随 Windows 界面语言；也可用 `--lang en` 或 `--lang zh` 指定。
- `Mini 浮窗`：切换到可缩放的小窗口，共用完整窗口的数据刷新；也可用 `--mini` 直接启动浮窗
- `到底部`：将日志滚动到最新内容，并恢复底部跟随
- `Esc`：关闭窗口

**Mini 浮窗**显示服务状态、运行时间、精简 GPU 信息和可滚动的槽卡。槽卡包含 token 用量/上限、已生成、缓存和当前速度；不支持槽明细的后端会显示提示。浮窗保留可拖动的原生标题栏，支持`完整窗口 / Full`、`暂停 / Pause`、语言切换和独立置顶；双击窗口内的服务标题也可恢复完整版。浮窗右上角 `X` 会退出整个监控程序。

## 四、命令行参数

全部可选，不填就是自动发现。

| 参数 | 默认 | 说明 |
|---|---|---|
| `--port N` | 自动 | 指定服务端口；给了就不再自动搜索 |
| `--host H` | `127.0.0.1` | 服务地址 |
| `--uiport N` | 服务端口+1 | WebUI 按钮打开的端口 |
| `--log-file P` | 自动 | 指定日志文件；给了就只盯这个文件 |
| `--log-dir D` | 自动 | 指定日志目录 |
| `--interval N` | `1000` | 刷新间隔（毫秒），最小 200 |
| `--pid N` | — | 只监控指定进程号的服务 |
| `--no-topmost` | — | 启动时不置顶 |
| `--mini` | — | 直接以 Mini 浮窗启动 |
| `--list` | — | 只列出发现到的服务，不开窗 |
| `--lang en/zh` | 跟随系统 | 选择英文或中文界面及列表输出 |

示例：

```
LlamaMonitor.exe                      # 全自动
LlamaMonitor-cli.exe --list           # 看看发现了什么
LlamaMonitor.exe --port 8080          # 指定端口
LlamaMonitor.exe --interval 500       # 半秒刷新
LlamaMonitor.exe --no-topmost         # 不置顶
LlamaMonitor.exe --mini               # 直接启动 Mini 浮窗
```

## 五、常见问题

**Q：说"未发现服务"，但我明明在跑？**
1. 先跑 `LlamaMonitor-cli.exe --list` 看发现了什么。
2. 列表为空说明端口不在自动探测范围内，用 `--port` 指定。
   自动探测的端口：8080, 11434, 1234, 8000, 30000, 5001, 5000, 1235, 8081。
3. 服务监听在 `0.0.0.0` 时会自动改用 `127.0.0.1` 去连。

**Q：显卡那行显示"nvidia-smi 无输出"？**
没有 NVIDIA 卡，或 `nvidia-smi.exe` 不在 PATH。程序仍可用，只是不显示显卡信息。

**Q：槽位表和任务表是空的？**
可能：① 当前连的不是 llama.cpp（其它后端没这些数据）；
② 服务此刻没有任务在跑；③ 任务表需要日志文件，用 `--log-file` 指定。

**Q：读不到另一个用户的 llama-server？**
读取进程命令行需要权限。以管理员身份运行本程序即可。

**Q：会拖慢推理吗？**
监控请求使用只读 GET，不发生成任务；实际资源开销取决于刷新频率和当前服务。
程序会在自身目录写入 `monitor-diag.log` 记录发现过程和异常，文件大小封顶 1 MB。

## 七、重新编译

源码是 C# / WinForms，用 .NET Framework 自带的编译器即可，**不需要装 .NET SDK**：

```
build.cmd
build.cmd "release-build"
```

脚本从系统 .NET Framework 安装目录寻找 `csc.exe`，按 C# 5 编译 `src` 中全部八个源码文件。默认输出位于 `dist` 目录中的桌面版和控制台版 EXE；第一个参数可指定其它输出目录。源码仓库忽略 `dist` 生成物；不想编译可下载 GitHub Release 中的 Windows 压缩包。

运行本地检查：

```
test.cmd
```

检查使用本地模拟服务和日志 fixture，覆盖 token 字段、运行时间来源、日志阅读位置及中英文完整/Mini 窗口。测试程序和窗口渲染结果写入 `dist\tests`；这些检查不替代真实推理服务、其它电脑或人工目视验收。
